# Безкоштовні RPC для NEAR testnet (2026-11-12)

Привід: під час засіву (боти) і E2E безкоштовні FastNEAR і dRPC відповідали `-429 Rate limits exceeded`, вхід нового гостя тягнувся понад хвилину. Сервер (Наварх, API, лідерборд, засів) ходить з однієї IP, тому ліміт на IP вичерпується саме там. Браузер кожного гравця ходить зі своєї IP.

Перевірено живими запитами (30 викликів `call_function config` поспіль, під час засіву):

| endpoint | результат | середня затримка | примітки |
|---|---|---|---|
| `https://rpc.testnet.fastnear.com` (і `test.rpc.fastnear.com`) | 30/30 | ~105 мс | ліміт не опубліковано, у пікові хвилини 429 |
| `https://near-testnet.drpc.org` | 30/30 | ~160 мс | у документації NEAR ~2100 CU/с |
| `https://api.zan.top/near-testnet` | 30/30 | ~330 мс | без ключа, у документації ~20 запитів/с; `view_access_key_list`, `block`, `tx`, `gas_price` працюють |
| `https://testnet-rpc.intea.rs` | 30/30 | ~1600 мс | працює, але повільний, у ротацію не беремо |
| `https://archival-rpc.testnet.near.org` | 30/30 | ~3100 мс | сильно обмежений, лише як останній запас |
| `https://near-testnet.gateway.tatum.io` | 3/15, далі 429 | | без ключа ~3 запити/с |
| `rpc.testnet.near.org`, `rpc.testnet.pagoda.co` | застарілі | | NEAR вимикає публічні RPC з червня 2025 |
| Lava, BlockPi | 410 / закрито | | |

Рішення:
- Читання (перегляд ігор, лідерборд, вибірки) розподіляємо по колу між FastNEAR, dRPC і ZAN (`readProvider`, `rotate` у `server/src/lib/near.ts` і `web/src/lib/chain.ts`), кожне коло з перемиканням на наступний при помилці. Ліміти трьох провайдерів фактично складаються.
- Транзакції йдуть через впорядкований failover (`provider`), щоб nonce і хеш блоку брались з одного джерела.
- Лідерборд перебудовується раз на 10 хв пачками по 3 запити.
- Браузер отримує той самий список, CSP пропускає всі три origin.

Якщо цього не вистачить на суддівстві: безкоштовні ключі з вищими лімітами дають ZAN, QuickNode (15 запитів/с), All That Node (500K CU/добу), dRPC; ключ реєструє власник (потрібна пошта), сервер читає його лише зі змінної середовища.

## Ключі власника (2026-11-12, пізніше)
Власник зареєстрував ключі QuickNode і ZAN для NEAR testnet. Перевірка: обидва виконують `call_function`, `view_access_key_list`, `block`, `tx`, `gas_price`; 40 послідовних запитів без помилок (ZAN ~340 мс, QuickNode ~440 мс); при 20 паралельних QuickNode тримає ~15 запитів/с, ZAN з ключем трохи більше, решта отримує 429 і йде на наступний endpoint. Ключі лежать лише в змінних середовища сервера, у репозиторій і в браузерну збірку не потрапляють. Сервер читає по колу п'ять endpoint: dRPC, FastNEAR, ZAN без ключа, QuickNode, ZAN з ключем. Браузер лишається на трьох публічних. Після хакатону ключі перевипустити.
