# 0003. Сервер: Наварх і API

Дата: 2026-11-11. Статус: прийнято (етап 4).

## Процеси і ключі
- `admiral` (`server/src/admiral`): ключ `ADMIRAL_KEY` лише function-call на методи Наварха. Опитує `config` і `games_since` кожні `TICK_MS`, для кожної гри чиста функція `decide` вибирає дію: commit, answer, move, reveal, farewell, claim, wait, done. Рішення завжди беруться зі стану контракту, тож після рестарту чи невдалої транзакції наступний тік просто повторює правильну дію.
- `api` (`server/src/api`): ключ `SPONSOR_KEY` лише на `create_guest, register_player`. Гості, докази для Verify, історія скарбниці й карти. Ключа поля Наварха (`BOARD_ENC_KEY`) в API немає.
- Обидва пишуть в один SQLite (`node:sqlite`, WAL): Наварх свої таблиці (поля, відповіді, розкриття, ходи моделі), API свої (гості, знімки).

## Чому так
- **`node:sqlite`, а не better-sqlite3.** Без нативного модуля немає класу збоїв «зібрано не тим Node» (інцидент Pulse 2026-09-26).
- **near-api-js 7.4.0**, як у Psephex. 7.5.0-7.5.3 вийшли в день збірки, свіжі релізи в ланцюзі підпису не беремо.
- **Поле Наварха** генерується криптографічним RNG, шифрується AES-256-GCM з AAD `game:<id>` і пишеться в базу **до** відправки коміту, тож не буває кореня, який сервер не може відкрити. При читанні корінь перебудовується і звіряється з записаним.
- **Хід моделі**: тіло запиту береться з view `nauarch_request` і надсилається в NEAR AI байт у байт (клієнт з Psephex: `Accept-Encoding: identity`, підпис через `/v1/signature/<id>` з повторами на 404). Будь-яка помилка, тайм-аут `MODEL_TIMEOUT_MS` (20 с) або відмова контракту ведуть до `nauarch_fallback`. Без `NEAR_AI_API_KEY` Наварх грає лише детерміновано (офлайн-демо, SPEC 14); у UI це видно з `source` пострілу.
- **Наварх завжди розкриває поле після гри**: від цього залежать XP гравця за потоплені кораблі і кінематографічне розкриття.
- **Keeper**: Наварх сам викликає `claim_timeout`, коли спізнюється гравець, у тому числі в розстановці, щоб звільнити слоти `max_open_games`.
- **Знімки скарбниці й карти** API бере опитуванням view кожні `SAMPLE_MS` і пише лише зміни. NEAR RPC не вміє шукати події, а індексатор для 3 днів зайвий.
- **Ліміти гостей**: `GUESTS_PER_IP_HOUR` і `GUESTS_PER_DAY` у базі API плюс загальний rate limit; поверх цього денний ліміт у контракті. Ключ, для якого гравець уже є, повертає наявний акаунт без транзакції.

## Засів карти
`npm run seed`: 30 ботів через справжній `/api/guest` з різними стилями розстановки (північний захід, краї, центр, випадкові), кожен грає повну партію проти Наварха. Під час засіву API запускають з `GUESTS_PER_IP_HOUR` ≥ 30, бо всі боти йдуть з localhost. У README позначаємо як засів (`Seed_01`…`Seed_30`).
